# План установчої зустрічі (Kickoff Meeting): Booking 3D

Цей документ є сценарієм проведення першої консультації та установчої зустрічі для студентської команди з **2 розробників та 3 дизайнерів**, що починають розробку клону сервісу бронювання житла Booking.com з 3D-візуалізаціями.

---

## ⏱️ Таймінг та регламент зустрічі (45 хвилин)

| Частина | Тривалість | Питання порядку денного | Відповідальний |
| :---: | :---: | :--- | :--- |
| **Частина 1** | **5 хв** | Візія проєкту, унікальність фічі 3D-турів, бізнес-мета для портфоліо | Керівник / Ментор |
| **Частина 2** | **10 хв** | Презентація ролей у команді: 3 дизайнери та 2 розробники | Уся команда |
| **Частина 3** | **10 хв** | Огляд технологічного стека (React 18, Django 5 + DRF, PostgreSQL 16, 3ds Max) | Dev 1 & Dev 2 |
| **Частина 4** | **10 хв** | Протокол одночасного старту ("Cold Start") та пайплайн передачі 3D | Дизайнери 1, 2 + Dev 2 |
| **Частина 5** | **10 хв** | Чеклист на перший спринт (Sprint 1), правила комунікації, сесія Q&A | Керівник |

---

## 📋 Детальний зміст зустрічі

### Частина 1: Презентація візії проєкту (5 хв)
- **Головна мета**: створити функціональний MVP сервісу оренди житла, де замість стандартних плоских фотографій користувач може роздивитися високоякісні 3D-рендери інтер'єру з різних ракурсів.
- **Наскрізний сценарій**: `ПОШУК ➔ ВИБІР ЖИТЛА ➔ 3D-ПЕРЕГЛЯД ➔ ВИБІР ДАТ ➔ БРОНЮВАННЯ ➔ МОЇ БРОНЮВАННЯ`.

---

### Частина 2: Розподіл зон відповідальності (10 хв)

#### Команда дизайнерів:
1. **Дизайнер №1 (3D / 3ds Max)**: створення 3D-сцен інтер'єру, геометрія, освітлення, реалістичні текстури, рендер 3–6 ракурсів, експорт в оптимізований WebP.
2. **Дизайнер №2 (UX/UI Lead)**: аналіз Booking.com, User Flow, Wireframes, інтерактивний прототип, Design System та макети клієнтського сервісу.
3. **Дизайнер №3 (Brand & Dashboard UI)**: назва бренду, логотип, брендбук, макети кабінету власника та адмінпанелі, фінальний проморолик 30–60с.

#### Команда розробників:
1. **Розробник №1 (Backend & DevOps Lead)**: інфраструктура Docker Compose, PostgreSQL 16, архітектура Django 5 + DRF, 11 моделей Django ORM, SimpleJWT, пошук, фільтри, транзакційна бізнес-логіка бронювання, Django Admin.
2. **Розробник №2 (Frontend Lead)**: React 18, TypeScript, Tailwind CSS, AuthContext, клієнтські екрани, інтерактивна 3D-галерея інтер'єру, кабінети гостя та власника.

---

### Частина 3: Технологічний стек та інструменти (10 хв)
- **Frontend**: React 18, TypeScript, Tailwind CSS, Lucide Icons, Vite.
- **Backend**: Python 3.11+, Django 5+, Django REST Framework (DRF), SimpleJWT, Swagger UI (drf-spectacular), Django Admin (`/admin/`).
- **База даних**: PostgreSQL 16 (11 моделей Django ORM).
- **3D-пакет**: Autodesk 3ds Max + Corona Renderer / V-Ray.
- **Сховище медіа**: Django Media Storage / Cloudinary для WebP зображень.

---

### Частина 4: "Cold Start" — чому розробники не чекають фіналу від дизайнерів (10 хв)
- **Дні 1–3**: Дизайнери узгоджують кольорові токени (`Primary`, `Secondary`, `Accent`) ➔ Фронтендер записує їх у `tailwind.config.js`.
- **Тиждень 1–2**: Дизайнер №2 видає чорно-білі **Wireframes** ➔ Розробник №3 верстає сітку та блоки на Tailwind без декору. Бекендери пишуть моделі Django та ендпоінти DRF.
- **Тиждень 3+**: Дизайнер №2 віддає фінальний **Figma UI Kit**, а Дизайнер №1 — перші 3D-рендери ➔ Розробники інтегрують реальний інтерфейс та галерею.

---

### Частина 5: Чеклист на перший спринт (Тиждень 1)
- [ ] Створити спільний робочий простір у Telegram / Discord.
- [ ] Створити GitHub-репозиторій та підключити гілкову модель (`main`, `develop`, `feature/*`).
- [ ] Розгорнути Docker Compose з PostgreSQL та Django 5 бекендом; перевірити підключення.
- [ ] Дизайнерам обрати референси 2–3 квартир для 3D-моделювання та розпочати побудову стін у 3ds Max.
- [ ] Затвердити час щотижневого загального синку команди (наприклад, щопонеділка о 18:00).
